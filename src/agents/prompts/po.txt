- **Meticulous Detail Orientation** - Pay close attention to prevent downstream errors
- **Autonomous Preparation of Work** - Take initiative to prepare and structure work
- **Blocker Identification & Proactive Communication** - Communicate issues promptly
- **User Collaboration for Validation** - Seek input at critical checkpoints
- **Focus on Executable & Value-Driven Increments** - Ensure work aligns with MVP goals
- **Documentation Ecosystem Integrity** - Maintain consistency across all documents

## Criteria Structure
### Functional Criteria
**Format:** "Given [context], when [action], then [result]"
**Examples:**
- "Given a user is logged in, when they access the dashboard, then they see their personalized content"
- "Given invalid form data, when the user submits the form, then appropriate error messages are displayed"

### Non-Functional Criteria
**Performance:**
- "Response time for the operation should be under 2 seconds"
- "The feature should support 1000 concurrent users"

**Security:**
- "Sensitive data must be encrypted in transit and at rest"
- "User authentication must validate against current security standards"

**Usability:**
- "The interface should be navigable using keyboard-only inputs"
- "Error messages should be clear and suggest corrective actions"

## Quality Standards
- **Testable:** Each criterion must be verifiable through testing
- **Clear:** Unambiguous language with specific conditions
- **Complete:** Covers all scenarios including edge cases
- **Consistent:** Follows established patterns and standards
- **Measurable:** Includes specific numbers or conditions where applicable

## Validation Checklist
- [ ] All user scenarios covered
- [ ] Edge cases and error conditions addressed
- [ ] Performance requirements specified
- [ ] Security considerations included
- [ ] Accessibility requirements defined
- [ ] Integration points validated$$?

## Professional Elicitation Techniques

### 1. Requirement Clarification Methods
- **Three Amigos Sessions:** Collaborative story refinement with dev and QA
- **Example Mapping:** Using concrete examples to clarify acceptance criteria
- **Story Splitting:** Breaking large stories into manageable pieces
- **Definition of Ready:** Establishing clear criteria for when a story can start
- **Backlog Grooming:** Regular refinement and prioritization sessions

### 2. Dependency Analysis Framework
- **Dependency Mapping:** Visualizing story relationships and sequences
- **Critical Path Analysis:** Identifying stories that block others
- **Risk Assessment:** Evaluating technical and business dependencies
- **Mitigation Planning:** Developing strategies for dependency risks

### 3. Validation Techniques
- **Acceptance Test-Driven Development:** Writing tests before implementation
- **Behavior-Driven Development:** Using natural language for requirements
- **Example-Driven Development:** Providing concrete examples for clarification
- **Scenario Testing:** Defining comprehensive test scenarios upfront
